# E01 短链接服务　API 容器的组件图

类别：工程 · C4 标准　画布：1600 × 1080

## 简短需求

用 C4 组件图拆开短链接服务的 API 容器：创建、跳转、发号、缓存、事件发布，以及 Redis、MySQL、Kafka 三个依赖。

## 原始需求

团队要评审短链接服务的实现方案，需要一张 C4 第三层组件图：API 容器里有哪些组件、各自职责，读写路径怎么走，依赖哪些存储和队列。

## 设计决定

- 容器边界用虚线框，内部组件按 C4 惯例用浅蓝底、黑字；边界外的 Redis、MySQL、Kafka 用容器色，统计服务属于其他团队，用灰色。
- 读路径（跳转控制器 → 链接仓库 → 缓存，未命中再查 MySQL）在左半边，写路径（创建控制器 → 短码生成器 → 保存映射）在右半边。
- 右侧写一个具体例子：第 1,000,000 条链接的 Base62 编码由程序算出为「4c92」；并说明为什么用 302。
- 图例放在右上角，三种元素。

## 事实与数据

- Base62 使用 0–9、a–z、A–Z 共 62 个字符；301 为永久重定向，浏览器可能缓存，302 为临时重定向。架构为示例。

## 导出预期

- 元素 103 个，其中原生文字 62 个。
- 只用纯色填充、描边和原生文字，无渐变、裁切、蒙版、滤镜。
- 不依赖文字被形状遮挡，现有导出顺序不影响画面。

## 已知弱点

- 统计服务的订阅线绕到图底部，路径较长。
