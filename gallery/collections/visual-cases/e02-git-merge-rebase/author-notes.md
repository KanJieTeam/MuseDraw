# E02 merge 和 rebase 有什么不同

类别：工程 · 终端暗色　画布：1600 × 1000

## 简短需求

终端风格对比 git merge 和 git rebase：同一个起点，两种操作后的提交图。

## 原始需求

新人培训讲 Git，大家总分不清 merge 和 rebase。想要一张终端风格的对比图：同样的提交历史，左边 merge、右边 rebase，看提交图怎么变，什么时候该用哪个。

## 设计决定

- 两块面板用同一组初始提交 A、B、E 与 C、D，只改变执行的命令，读者比较的是结果。
- merge 一侧多出一个有两个父提交的 M；rebase 一侧生成新的 C′、D′，原来的 C、D 变暗，表示不再被分支引用。
- 提交哈希是 7 位示例值，分支名与 HEAD 用 `git log --graph` 的括号写法。
- 底部各一句用法建议，rebase 的警告用红色。

## 事实与数据

- rebase 会重写提交，产生新的哈希；对已推送到共享分支的提交做 rebase 会给协作者带来冲突。哈希为随机示例。
