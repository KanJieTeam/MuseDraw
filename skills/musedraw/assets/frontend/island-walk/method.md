# A route as the main composition

Open `index.html` directly. This original fictional example uses inline SVG,
HTML, CSS and JavaScript, with no downloaded pictures or backend. Local font
availability can change its typography.

The composition joins three given stops with one continuous path. Selecting a
stop updates its adjacent description; choosing a period updates the itinerary
heading and all three times. Desktop uses a horizontal itinerary, while the
phone keeps the same sequence in a vertical reading path. All distances, terrain,
weather and availability beyond the supplied text remain unspecified.

Reuse the relationship, not its invented route or cream palette. Keep the SVG
landmarks, selectable labels and description mapping in agreement. When changing
stops or schedules, update their data, geometry, labels and itinerary together.
The schematic is not a navigable map. This example would not suit a task that
needs real geographic coordinates or verified travel times.

Its development comparison had two independent contexts inspect both versions
without source identities. Both preferred this version for the route task, while
noting small secondary labels and the missing times on the overview map. That is
limited design feedback, not human audience validation or a universal quality
claim. A mobile label/caption collision introduced during revision was found
and repaired before this version was preserved.
