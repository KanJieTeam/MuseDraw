# Plans: one reading order, several content-dependent arrangements

This original construction kit turns dated targets, undated work and shared
resources into a native composition. Its purpose is a readable internal plan,
not an imitation of an external artwork or a claim of universal premium taste.
See [the input contract](../../../references/plan-composition.md).

The visual decisions are executable:

- A requested title has its own scale and content-measured height.
- Period anchors repeat; metric units and scales stay separate.
- A compact numeric summary uses aligned large values. Magnitude comparison
  can use zero-based bars. No encoding implies completion.
- Work uses independent unboxed columns below the target region (a vertical
  relation layout for five workstreams), with text height from actual copy.
  The work grid is not the year grid and does not assign dates to activities.
- Common support is connected to work; it is not another fake process stage.
- Labels and actions remain inside their owning native node, with stable IDs.
- Content edits recompute layout. Named themes can change colour/material;
  readable type roles are owned by the method rather than inherited tiny text.
- Theme decoration is scoped to graphic marks; text-only work has no inherited
  card bars or plates. Required numeric copy uses ink for reliable contrast.

`community.json` uses illustrative planning facts. Replace them with supplied
facts, preserving support membership. It is a regression/development example,
not a user-approved gallery entry. The method leaves typography and geometry
explicit in generated `scene.json` for further custom edits.
