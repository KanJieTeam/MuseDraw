# Typed static system views

One `typed-system` family supports two views. Use `typed-system` as the
container example and `typed-context` as the context example. These are two
examples, not two independent layout families.

Context shows one focal software system, up to four people and six supporting
external systems. Each declared relationship must touch the focal system.
Container view expands one software-system boundary into up to twelve explicitly
grouped containers; the grouping bands are presentation groups, not C4 levels.
Cycles and reciprocal static links are accepted. Direction, responsibility and
declared technology remain attached to each relationship. An unknown technology
is displayed as unknown; it is not guessed from the node names.

The renderer computes measured text, visible object boundary ports, separate
orthogonal routes and label tracks. It does not delete a declared relationship
to simplify the page. Unreadable routes, oversized content, undeclared endpoints,
confused ownership or unsupported diagram levels must leave this route.
The existing architecture family remains available for its narrower DAG view.

Optional exact workload estimates in container view are independent calculations
against their own baselines. Do not add their manual remainders into a unique
document count. Context view does not accept that estimate panel.

Read the example JSON before mapping facts. This is neither a deployment nor a
component diagram, security perimeter, operational-success claim or clinical
validation. See the primary [C4 context](https://c4model.com/diagrams/system-context),
[container](https://c4model.com/diagrams/container) and
[notation](https://c4model.com/diagrams/notation) descriptions.

Run `node scripts/musedraw.mjs core example typed-context --out output/input.json`
and `node scripts/musedraw.mjs core render output/input.json --out output/view`.
Passing geometry checks does not establish aesthetic quality.

Two additional source-subject inputs are `meeting-booking-architecture` and
`sequencing-platform-architecture`. They retain relationships that exceed the
older architecture DAG route, including external-to-external or returning
connections. Their source assumptions remain notes, not verified performance.
An input matching a source does not establish a reproduction of its layout.
