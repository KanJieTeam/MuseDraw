# Reference Study Scope

## Boardmix software architecture category

Source: [architecture category](https://boardmix.cn/community/tag-1852), in the recommendation order used by the page's actual requests, `order=6`.

On 2026-10-10, all 32 contact sheets covering 621 unique public previews were actually inspected. The screening retained 354 structural references: 300 core references and 54 detail references; 267 were excluded. References include capability ownership, component integration and deployment boundaries. Organization trees, ordinary function trees and research/operational workflows are not core references for the current architecture scope.

These are preview-screening counts, not 621 complete-canvas close readings, 354 independent styles or certifications of engineering correctness. This batch additionally included inspection of 8 public full-canvas views; 6 URLs had not previously received close reading. Repeat inspections are not counted as new cases. The original catalog, image-load status, sheet-level observations and hashes remain in local study evidence, not routine prompt input.

Representative observations:

- [SDK component architecture](https://boardmix.cn/community/ap5fugAuRw2VNyKMCBhb-A/): nested ownership of interfaces, adapters and components, with a separate boundary for third-party dependencies. Do not add unsupported calls.
- [Microservices platform](https://boardmix.cn/community/bZFzfTfm6Dwt3F6S2bhMKg/): separate entry, business services and shared support. Nearby storage does not mean every service accesses it.
- [Data-asset platform](https://boardmix.cn/community/O_wa2m-_AGng5FC6vU_O-Q/): content-based groups and shared foundational capabilities. Keep the structure without copying the figure's heavy colors.
- [Hybrid-cloud deployment](https://boardmix.cn/community/dm1hTEXhsuhaZcAqShIu7A/): actual instances and cloud boundaries belong in a deployment view, not a capability matrix.

## Edraw program architecture category

Follow-up source: [program architecture category](https://www.edrawmax.cn/templates/1057/1/1), in the public pages' "Community Picks" order, with path order `1`. On 2026-10-10, the first 24 pages were frozen: 2,400 unique public previews. All 120 contact sheets were actually inspected across four parallel review streams, with checks of each sheet's 20 numbers, image loading and hashes. The category showed 41 pages at that time; this is not a claim of reviewing the entire site.

The screening retained 1,969 software-architecture structural references: 1,856 core references and 113 detail references; 431 were excluded. Organization/industry-chain/management-method diagrams, pure function trees, research workflows and obscured or unclear content are not core references. Combined with Boardmix, 3,021 public previews were screened, retaining 2,323 unique public URLs: 2,156 core references and 167 detail references. Similar figures are understood as families such as capability ownership, component integration, deployment and framework details; URL counts are not counts of independent styles.

Representative public-detail observations from this stage (ordinary web previews, not downloaded source templates):

- [Frontend/backend separation](https://www.edrawmax.cn/templates/file/1010253/): frontend ownership, gateway, shared services and storage have different roles. Old technology names and cluster counts in the template are not recommendations or system facts.
- [Microservices architecture](https://www.edrawmax.cn/templates/file/1011516/): separate entry, proxy, gateway, registry, services and side support. Distinguish containment from explicit connections without copying the multicolor skin.
- [Enterprise integration](https://www.edrawmax.cn/templates/file/1010249/): layers for applications, integration capabilities and runtime foundations, with shared security spanning them instead of being repeated in every layer. The source text and branding are not included in the Skill.
- [Software platform](https://www.edrawmax.cn/templates/file/1028024/): light ownership regions, white or softly colored child modules and side support can be designed separately. Not every domain needs the same sidebar.
- [ZooKeeper instance relationships](https://www.edrawmax.cn/templates/file/1079896/): distinguish roles from instances; reads, writes and synchronization cannot rely on color alone. Template node counts are not the user's deployment counts.
- [On-premises deployment](https://www.edrawmax.cn/templates/file/1031757/): environment domains, application-instance groups and data endpoints have different levels. Primary/replica names do not justify adding replication relationships absent from the material.
- [Soul components](https://www.edrawmax.cn/templates/file/1013516/): separate management and runtime; plugin chains and rule-processing components have their own ownership. Delivery and monitoring are not default additions to every figure.

Some default public-canvas views are cropped. Local observations are not presented as close readings of an entire figure. Additional detail observations help check structure but do not increase the unique-preview counts above. Complete screening files, sources and screenshot hashes remain in local study records; routine generation does not load that large catalog.

## Counting and permission boundaries

An earlier batch contained another 2,000 mixed-category recommended previews. It cannot be described as "2,000 software architecture diagrams" and is not added to the current architecture counts. The current scope is software architecture only; blank images, titles and repeated URLs are not used to inflate study counts.

The study produced original classifications, design rules and tool improvements, not model training. The Skill does not distribute community screenshots, template files, branded icons or authors' text. Public previews do not imply permission for open-source redistribution. Do not guess unreadable labels or treat a template's technology stack as facts about the user's system.

No fair comparison of token use with real models has been performed. Do not claim percentage savings or superiority over other Skills. Layout checks do not establish the user's aesthetic approval.
