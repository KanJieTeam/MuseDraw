# MuseCore resource allocation

## 适用范围

`resource-allocation` 只处理横向资源、纵向工作流的显式分配账本。读者要回答：每条工作流用了哪些资源，以及每类资源还剩多少登记容量。资源数和工作流数均为 2–8；每个交叉单元必须提供数值和来源。

模型只计算每类资源的已登记负载、容量减负载后的余量和 `spare / balanced / over` 状态，不推断人员可用性、排班、交付承诺、质量、预测或因果关系。零分配也必须显式登记。汇总按输入数值的十进制表示计算，避免二进制浮点尾差制造超额状态；不使用容差抹掉真实的小额差异。

## 路由契约

调用者必须声明 `readerTask: "resource-allocation"`、`evidenceType: "quantitative"`、`hasRawData: true` 和 `resourceKind: "resource-workstream-load"`，并给出 `resourceCount`、`workstreamCount`。不满足这些条件时，路由器拒绝或要求改用自定义表示。

## 输出与复现

输入 JSON 由模型校验后交给 `resource-allocation` 图形族，输出 SVG、PNG 和离线 HTML。图面采用资源列、工作流行、负载条和余量账本；每个单元按 `resourceId` 对应到资源列，输入数组顺序不会改变对应关系。每个单元保留来源，不把余量画成建议。

列宽按完整数值和容量文字测量，画布随列数扩展；剩余横向空间均分到资源列，使最小输入的矩阵也与页首、余量账本对齐。表头、工作流行和页脚按实际字体高度换行，余量账本每行最多四项。保持固定字号，无法在允许行数内排下的文字直接拒绝；不删字、不缩字号。数量超范围或存在缺失单元也会拒绝。

比例条只在容量大于零时出现，达到容量后停止在轨道末端；超额仍以完整数值及“超出登记容量”文字标明。容量为零时只显示零容量状态，不绘制比例条。右栏按同一个单位汇总工作流负载，与资源总容量比较，不将零分母显示为 0%。

## 视觉检查

先看横向资源列是否仍可比较，再看工作流行的总量和余量是否能回查到单元格。窄屏预览必须允许横向阅读但不能产生浏览器溢出；中文长标签和字体压力不得遮挡或越界。
