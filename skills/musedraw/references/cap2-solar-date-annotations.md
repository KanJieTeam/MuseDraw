# Explicit approximate date annotations on the existing solar-term wheel

The original longitude catalogue, season model, ink ring and metric-responsive
radial collision solver are reused. No second solar-term or ephemeris model is
introduced. The unannotated default renderer keeps its exact route and bytes.

Optional `termAnnotations` contains 0..24 explicit entries. Each entry has a
selected catalogue `id`, an `approximateDateLabel` (1..28 characters) and `note`
(explicit null or1..60 characters). Duplicate, unknown or unselected IDs reject.
A date label must retain approximate wording such as `前后`, `约` or `around`;
labels are never parsed as dates or authenticated. Annual dates, leap years,
timezones and local phenology are not inferred from solar longitude.

Names and longitudes remain generated by the existing model. Each supplied date
and note is added underneath that term's longitude with actual measured line
boxes. Existing radial layout recomputes label radius, ring radius and canvas;
no manual positions or font reduction. Annotation prose may occupy at most four
lines. The original bounded radius budget refuses excessive combinations rather
than discarding labels or notes. Missing annotations stay absent, and an explicit
empty array invents no dates. Newly annotated geometry uses compositionReference;
it never labels arbitrary caller annotations as a source replay.

The example preserves the source's24 approximate labels. Changed start term,
selected terms, supplied longitude pointer and annotations recompute through the
same existing layout. Execution geometry checks are separate from source reading
and aesthetic judgement. Actual Noto SC/CJK normal/+40 rendering is required by
the browser test; use `MUSECORE_NOTO_FONT`, legacy alias or a standard font path.
Absence fails explicitly and is never skipped. The optional annotation guard is included in the normal registered
`solar-terms-wheel` route; the unannotated branch remains available.
