# Explicit parallel-training and statement comparisons

`parallel-training` coordinates independently supplied data-, tensor- and
pipeline-parallel comparison scenarios, not an inferred hybrid placement. Ideal
ring payload is calculated per device for send and receive separately. Tensor
partitions and equal-time GPipe flush dependencies use explicit dimensions and
microbatches. The independent memory panel uniformly partitions only listed
states; activations, temporary buffers and runtime overhead are excluded. A
negative margin stays negative. These are not measured throughput, wall-clock
scheduling, training results or a guarantee that a real model fits a GPU.

`three-statements` uses a closed teaching account set with supplied opening and
closing values. Explicit additions and subtractions cross-check net income,
cash/noncash relationships and statement balances. Missing inputs and genuine
reconciliation differences are rejected rather than filled to make totals agree.
The result is a bounded teaching relationship diagram, not a complete accounting
standard implementation or an audit of a real business.

Use `core example parallel-training` or `core example three-statements`, inspect
the schema, then `core render`. Existing expression, dependency-scheduling,
typography and routing tools are reused by their separate whole-page
constructions. Unsupported schedules or accounts need another route. Tested
execution does not establish operational performance or aesthetic approval.
