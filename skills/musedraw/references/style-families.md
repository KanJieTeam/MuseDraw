# 风格家族与子风格

用户可以只说“墨蓝风格”，也可以在已有图的对话里说“换成墨蓝”。从当前资料保留内容，选择适合阅读任务的子风格；不要求用户记住案例编号、完整模块清单、坐标或色值。没有任何内容上下文时，只问要画什么。

## 家族决定气质，子风格决定表达

| 用户名称 | 兼容工具 ID | 视觉语言 |
| --- | --- | --- |
| 墨蓝 | `enterprise-blue` | 墨蓝重点、雾灰归属、白色内容；标题使用深蓝墨色，不混入绿色 |
| 石墨 | `technical-ink` | 白底、墨色文字、灰阶边界，关系与技术标识符更突出 |
| 青灰 | `slate-teal` | 低饱和青灰与蓝灰，清楚区分主域和贯穿支撑 |
| 暖砂 | `editorial-sand` | 暖砂底域、棕色重点、少量灰蓝关系线 |
| 松绿 | `forest` | 深绿重点与白底，边界保持低饱和 |
| 柔彩 | `soft-domains` | 雾蓝归属、小面积暖色强调，不逐域换成彩虹 |
| 夜幕 | `dark-system` | 炭黑画布、灰白文字、明暗边界和低饱和蓝色重点 |

每个家族都包含以下三种子风格。它们共享语义色值，不是三套换色皮肤。

| 子风格 | 工具 ID | 适用表达 |
| --- | --- | --- |
| 轻线留白 | `quiet` | 细线边界、留白、较少大面积实色；默认用于组件、集成和部署视图 |
| 实色层带 | `banded` | 标题带聚合层级，白色子模块承载正文；默认用于能力归属视图 |
| 紧凑分区 | `compact` | 缩短模块和分区间距，不缩小正文来塞字；适合信息密集的总览 |

“轻一点”可以选择轻线留白；“紧凑一些”可以选择紧凑分区。用户已明确子风格时优先保留；密度调整与子风格可以分开，例如轻线边界也可以紧凑排列。

## 保留与变化

固定：角色配色、字体栈、标题层级、边界线条与最小正文字号。

随内容调整：容器宽高、行列数、文字换行、画布、支撑栏位置和关系路由。内容少时不补空模块；长名称不裁短或逐字竖排；没有侧栏或循环关系时，不继承参考图的侧栏和循环。

布局由实际分组、关系、数量和用途决定。风格不决定业务模块、运行调用、厂商、协议、性能或部署实例。能力包含关系不等于运行调用，也不等于物理部署。

## 可执行接口

```sh
python <skill>/scripts/style_tokens.py 墨蓝
python <skill>/scripts/style_tokens.py 墨蓝 --view component
python <skill>/scripts/style_tokens.py 墨蓝 --variant quiet --density compact
```

Python 接口：`resolve_style(identifier, variant=None, view="capability", density=None)`。

- `identifier`：用户名称、英文别名或兼容 ID；未知家族报错，不偷偷换成默认蓝色。
- `variant`：可省略；由视图和显式密度选择，不需要用户指定。
- `view`：`capability`、`component`、`integration`、`deployment`。
- `density`：`normal`、`compact`、`comfortable`，可使用中文“常规／紧凑／宽松”。
- 结果包含 `colors`、`detailColors`、`fonts`、`typography`、`stroke`、`weights` 和 `layoutRules`。几何组件读取这些值，不重新发明近似色。

当前实现是风格解析和可执行的视觉规则；它本身不生成布局或判断系统事实。内容驱动绘图工具覆盖的结构可直接调用，未覆盖的复杂拓扑仍需要按原生 SVG 设计与实际渲染检查。不能把三个 token 配置称作所有视图的自动布局完成。

## 验证

换业务、模块数量、长短文字和执行智能体，检查风格是否稳定。至少检查语义内容完整、无旧案例文案残留、字不出框、标题留白、边界与关系，以及全图和缩小后的层级。颜色、元数据或脚本测试通过不等于审美验收；仅墨蓝校准稿已获用户认可，其他家族与新内容仍须看图。
