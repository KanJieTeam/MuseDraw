# MuseDraw

## MuseCore · the shared creative workflow

**Understand the brief → jointly decide the work → make and deliver it.**
MuseCore couples this shared design method with executable composition tools.
The bundled runtime computes bounded layouts from content and explicit
relations; it is not a separate model or a general aesthetic engine. Apply the
shared method across production media.

1. **Understand the brief.** Identify the audience, use, content facts, supplied
   assets/style and delivery requirements. Carry forward decisions the user has
   already made. Ask only when a missing fact materially changes the work.
2. **Form one work proposal through three collaborating capabilities:**
   **表达判断 / expression judgement** decides emphasis, information, relationships
   and evidence; **视觉立意 / visual conception** decides the subject, composition
   and reading path; **风格编排 / visual orchestration** coordinates type, imagery,
   colour, space and material. Work on them together: they are neither three
   sequential passes nor three required agents. A new visual idea can change the
   information arrangement; the evidence and medium can change the visual idea.
   The proposal resolves **content structure, the main visual, visual language,
   and asset/medium responsibilities**. Keep this proportionate and internal;
   a simple task does not need a plan file or a planning speech.
3. **Make and deliver the work** through the appropriate route below. Check facts,
   functioning and actual appearance separately; keep the finished work, useful
   editable source and assets. Passing an exporter is not an aesthetic verdict.

**去 AI 味 runs through the decisions and production.** Replace a default treatment
when it weakens this subject; do not substitute a compulsory sparse layout,
black disk, muted palette or overlapping-circle motif. Preserve richness and
detail that help the work. For original explanatory work, a difficult composition
or a visible design failure, read [MuseCore decisions](references/musecore.md)
before choosing the composition, together with only the relevant production
reference. Exact replay, a local text edit and the RAG starter retain their fast paths.

**Enhance on demand.** When the direction is unresolved, test a sketch or key
region and return to the affected decision or production step. Do not make every
request wait for multiple full designs or extra reviewers. Preserve first drafts
and failed attempts during sustained testing; the user's aesthetic judgement
governs when they are reviewing the work.

**Accumulate separately from the main creation path.** Project facts and user
preferences stay in project memory. Candidate design methods record their
conditions, evidence and failures; try them with new content before promoting
them into shared method/style resources. A downloaded case, replay or corrected
development subject is not evidence of general improvement.

## Choose the production medium

Choose the production route from the requested work and its editing needs.
The bundled scene renderer is one tool within MuseDraw; it does not define the
scope of the assistant or require every artifact to be a diagram.

For a named style, original visual direction or a more expressive poster/report,
use [MuseDraw visual language](references/visual-language.md): develop the existing
twenty families through their typography, imagery, spatial rhythm and material.
For original Swiss or Ink Wash work, use the matching
[working style kit](references/visual-language.md#working-kits-for-new-subjects):
it pairs composition choices, object drawing tools and type roles for new content.
For other named styles, or when a complete work is the useful starting point,
inspect a relevant composition using [style compositions](references/style-studies.md).
Use it to resolve the relationship between objects, type, colour area and space;
then use the theme JSON for production settings. Carry over decisions that fit
the new content, not its subject, measurements or page coordinates. If no work
fits the task, use the family guidance and make the new spatial argument directly.
Keep the requested medium; a style name does not require a scene or box layout.
Exact replays, local edits and semantic composers retain their fast paths.

Use the known installed Skill directly. Read only the reference for the chosen
route, rather than scanning every style or example. When the user says that
installed copy was updated, reread this entrypoint and the selected reference;
older conversation descriptions may refer to a different workflow.

For repeatable content-driven work, discover the bounded MuseCore families with
`node scripts/musedraw.mjs core list --compact`, then read only the matching
reference. Choose by reader task and data structure, rather than a palette.
The host supplies facts, content and asset selection; the program owns the
family's encodings, coordinated geometry and placement.

- **Painting, photographic imagery, textured illustration or image editing:**
  read [image work](references/image-work.md) and use an available host image
  generation/editing tool. Deliver the resulting PNG/JPEG or requested image
  format with useful source prompts/assets; do not manufacture an SVG or scene
  solely to satisfy the diagram workflow. Actual image synthesis requires that
  host capability; the scene engine does not generate painterly pixels.
- **Poster, brand visual or mixed composition:** choose native vector/HTML
  typography, image assets or a combination as the subject and editing needs
  require. Use the image route for raster imagery and the scene route for a
  native-vector example. Preserve the selected example's production medium.
- **Explanatory diagrams and editable schematics:** read the
  [scene workflow](references/scene-workflow.md) when a scene fits the objects
  and relationships. Keep those facts intact. Measured data use the plotting
  route below. SVG is an editable output here, not a global format rule.

For measured data, report charts and statistical figures, read
[data figures](references/data-figures.md). Use an available plotting tool;
the supplied data-plot helper handles line, scatter, bar, explicit intervals,
paired changes, raw observation distributions and measured heatmaps. This route
does not require scene geometry. For mechanisms and physical
objects use [scientific composition](references/scientific-design.md).

For everyday office processes, task ownership and project plans, read
[office diagrams](references/office-diagrams.md). Choose the appropriate flow,
responsibility matrix or time-based composition from the actual work; do not
turn every office brief into the same card grid or infer missing assignments.

For monochrome technical-report figures using layers, record association,
content assembly with review, one conditional return, stage-by-role lanes or
grouped time intervals, use the
[executable MuseCore report compositions](references/musecore-runtime.md) when
their scope matches. `node scripts/musedraw.mjs core list` discovers the content
examples; `core render` computes PNG, SVG and an offline editable page. Preserve
all required facts and relations; choose another route if they exceed the
family instead of deleting them to fit.

For a new office or research diagram, read [representation routing](references/representation-routing.md)
before drawing. Declare the reader question and one primary representation in
`scene.meta`. The representation is a hard production choice: do not silently
fall back to a generic architecture card wall when the content does not fit.
Run `node scripts/representation-lint.mjs scene.json --strict` before delivery;
an equal-card-wall or missing representation is a failed first draft, not an
invitation to shrink text or add more boxes.

For a composed office or research report page, [report spreads](references/report-spreads.md)
provides editable compositions for business, project and research reports,
with typography, actual data charts and optional artwork. Adapt a composition
when its content structure fits; standalone
data figures keep the plotting route above.

For an interface prototype or work UI, read [frontend decisions](references/frontend-design.md).
For record review, coordination or operations, also read
[working applications](references/frontend-work-apps.md). Implement runnable
HTML/CSS/JavaScript or use the project's existing frontend stack, then deliver
source and browser previews. This route does not require a scene or scene-engine
render. The diagram instructions below apply to drawings and scene artifacts.

For a native-vector poster, information graphic, teaching explanation or scientific
multi-panel artwork, use the [visual case library](references/case-library.md) to
find a relevant example and its design method. The small registry covers 180
included cases; read only the selected case. Approved native-vector artwork uses
the existing replay route and keeps its composition, including a poster headline
or necessary figure panels. These examples are editable sources, not a promise of
automatic parameterised layouts or a reason to impose one style on every task.

For scene-based diagrams, translate the user's facts into visible objects and
relationships. The semantic `compose` route owns repeatable layout, reading size,
role styling and ports when its grammar fits. Use a custom scene for other
relationships; the [scene workflow](references/scene-workflow.md) covers those
choices, runtime reuse, rendering, checks and continued edits.

For native object diagrams showing changes, comparisons, feedback, shared routes,
detail views and layers,
use the matching [object-composition method](references/object-composition.md).
Make the relationship visible in the drawing; don't replace it with explanatory
cards. The engine's `object-views` block keeps repeated native objects consistent.

## Native scene production

For a scene drawing, native-vector replay or structural edit, read the
[scene workflow](references/scene-workflow.md). It contains the semantic routes,
font/browser preparation, diagram style selection and scene schema links.
Render with `scripts/musedraw.mjs`, read `checks.json`, and keep PNG, SVG and
editable scene sources. These instructions apply to scene artifacts; measured
plots, image synthesis and runnable interfaces retain their own production route.
Scene headings and footers are off unless requested; preserve an explicitly
selected example's intended composition.

For the standard shared-index RAG starter, run immediately:

```sh
node <skill>/scripts/musedraw.mjs quickstart rag --lang zh --out output/rag --strict
```

Use `--lang en` for English. Read the scene workflow's runtime section only if
preparation is needed; the starter does not require schema, theme or gallery
research before its first render.
