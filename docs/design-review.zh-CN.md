# 图稿评审

本轮先评审十二张候选。每张把原参考、此前稿与当前稿放在一起，
附源文件、绘图规则和检查记录。已修改与未修改的稿件分别标出。

请设计师重点看：

- 不同图是否有真正不同的构图、信息密度和关系表达，而非同一模板换色。
- 参考的视觉特征是否保留；哪些调整改善了阅读，哪些丢失了原作质感。
- 配色、字阶、边距和连线的具体问题，标出图号与位置即可。
- 样式能否用于新的内容；精修稿不直接等同智能体原样输出。

## 制作离线评审包

选图清单包含恰好十二项 `cases`，文件路径相对清单所在目录。
每项需要 `number`、`title`、`image`、`svg`、`before`；
`drawio`、检查记录和参考来源可附上。编号只用于评审，不是用户绘图时的要求。

```sh
python scripts/build_designer_review.py --selection path/to/selection.json --output output/designer-review
```

产物包括可直接打开的 `index.html`、原生源文件、当前 Skill 源码、
检查记录、压缩包和 SHA-256 文件清单。选择清单内的链接会转换为包内路径，
本机绝对路径会脱敏；现有输出与输入图稿不会被覆盖。

默认只保留第三方参考的来源链接。确有内部对照需要时，追加
`--private-references`，包会明确标成内部审阅版。不要将这类截图包推送仓库
或作为公开宣传素材；公共可见不代表取得再分发授权。

## 检查的边界

[MuseDraw Skill](../skills/musedraw/SKILL.md) 的短描述入口无需坐标或色值。
当前分组渲染器支持风格、正文测量及已有布局中的关系路由，
并非适合任意拓扑的自动构图器。密集关系可能仍需原创 SVG 布局；
不能为了通过检查删除用户给出的返回路径或合并不同关系。

程序通过只说明相应检查通过。审美认可、真实系统事实、
实际模型复现和 draw.io 编辑交互分别记录，不由几何检查代替。
回归中遇到的失败样本应保留，后续与修正结果一起复核。
